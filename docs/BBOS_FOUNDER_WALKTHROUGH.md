# BBOS Founder Walkthrough Guide

**Purpose:** Test Phase One as a first-time customer — not as the author.  
**Status:** Read-only test protocol. Does not change the frozen product.  
**Companion:** `docs/BBOS_PHASE_TWO_USABILITY_BACKLOG.md`  
**Phase One tag:** `bbos-v1-phase1` (do not modify tagged assets during this test)

---

## What this is

The Founder Walkthrough is a structured usability session. You pretend you have never seen BBOS. You complete Modules 1–4 using the Main Guide, Pricing & Margin Calculator, and Weekly Operating Rhythm Workbook.

You do **not** fix anything during the session. You only record friction.

> **NOTE**  
> This guide does not replace the Main Guide. It tells you *how to test*. The Main Guide and tools tell you *how to operate*.

---

## Recommended test business

Use **Maya’s Property Services** (canonical fictional example) **or** another clearly fictional service business.

Rules for the test business:

- Invent names, jobs, and numbers that are obviously fake.  
- Do not use real client names, real prices, addresses, access codes, credentials, or private records.  
- Do not use VelocityMaid, Bornfidis client, or other confidential operational data.  
- If you “use Bornfidis Provisions” as a thought experiment, still use **fictional** figures only.

---

## Testing rules (read before you start)

1. **Do not edit files during the walkthrough.** No guide edits, no workbook redesign, no calculator changes, no script changes.  
2. **Do not fix issues immediately.** Log them. Sleep on them. Review later.  
3. **Complete the full journey first.** Partial testing biases what you notice.  
4. **Use only fictional data.**  
5. **Test both a normal week and one disrupted week.**  
6. **Record uncertainty honestly.** “I guessed” is useful evidence.  
7. **Distinguish content issues from tool issues.** Was the idea unclear, or was the sheet hard to find?  
8. **Distinguish blockers from preferences.** “I would prefer blue” is not a blocker.  
9. **Think like a busy owner.** If a step only works when you are calm and have two free hours, say so.  
10. **Do not push, deploy, or reopen Phase One locks** as part of this test.

---

## Severity definitions

Use one severity per backlog entry:

| Severity | Meaning |
|---|---|
| **Blocker** | The owner cannot complete the task, or risks making a serious mistake (wrong price logic, wrong stage, silent data risk, etc.). |
| **Friction** | The task can be completed, but instructions, layout, terminology, or flow cause hesitation, rereading, or back-and-forth. |
| **Nice-to-have** | The task works; improvement would add convenience or polish only. |

## Session setup (10 minutes)

1. Open this guide and the usability backlog template.  
2. Choose your fictional business.  
3. Open Module 1 and the Rhythm Workbook (copy).  
4. Set a timer for the whole session (suggest 2–4 hours with breaks).  
5. Write today’s date at the top of your backlog.  
6. Remind yourself: **collect, don’t fix.**

## Part A — Module 1: Business Foundation

### A1. Cost-of-Disorder Audit

**Do:** Complete the audit with 6–9 concrete fictional leaks across Time, Money, and Capacity. Write the single most expensive pattern sentence.

**Tool:** Workbook sheet `Cost of Disorder` (and/or paper).  
**Guide:** Module 1, Chapter 1.1.

### A2. Owner’s Time Map

**Do:** Log at least three fictional days (ideally seven) into Doing / Selling / Running / Building. Note which bucket surprised you.

**Tool:** Workbook sheet `Owner Time Map`.  
**Guide:** Module 1, Owner’s Time Map.

### A3. One-Page Business Snapshot

**Do:** Fill all six Snapshot fields. Choose **one** first weakness.

**Tool:** Workbook sheet `Business Snapshot`.  
**Guide:** Module 1, One-Page Business Snapshot.

**Pause check:** Could a stranger tell what the business is and what to fix first from this page alone?

---

## Part B — Module 2: Offer and Sales System

### B1. Offer Builder

**Do:** Complete Who / Intended outcome / Included / Optional / Not Included for the core offer. Keep Optional **named but unpriced**.

**Tool:** `Offer Builder`.  
**Guide:** Module 2, Offer Builder.

### B2. Included / Optional / Not Included boundaries

**Do:** Re-read your boundaries. Confirm a busy owner could hand this to a helper without inventing scope.

**Pause check:** Is “Not Included” strong enough to prevent scope creep?

### B3. Offer Ladder

**Do:** Define Entry / Core / Premium. Use `[price — set in Module 3]` placeholders only.

**Tool:** `Offer Ladder`.  
**Guide:** Module 2, Offer Ladder.

### B4. Offer One-Pager

**Do:** Draft all six parts. No prices. One clear how-to-start action.

**Tool:** `Offer One-Pager`.  
**Guide:** Module 2, Offer One-Pager.

### B5. Pipeline Tracker

**Do:** Enter 3–5 fictional opportunities across stages Lead → Qualified → Proposed → Won / Lost. Every live row needs a next action.

**Tool:** `Pipeline Tracker`.  
**Guide:** Module 2, Visible Pipeline.

### B6. Should I Say Yes?

**Do:** Run the five checks on each Lead you consider qualifying. Record Yes / Not now / No with one-line reason. Put Not now back in Lead with a revisit date.

**Tool:** `Should I Say Yes`.  
**Guide:** Module 2, Should I Say Yes?

### B7. Follow-Up Cadence

**Do:** Write 3–4 rules (Trigger → Action → Timing) covering new lead, proposal, final nudge, and stop/Lost.

**Tool:** `Follow-Up Cadence`.  
**Guide:** Module 2, Follow-Up Cadence.

**Pause check:** Could you run this cadence in under 45 minutes mid-week?

## Part C — Module 3: Pricing With Dignity

### C1. Build a Cost Stack

**Do:** Build a fictional Core Cost Stack (and optionally Entry / Premium layers) using Module 3 method.

**Tool:** Calculator `Inputs` sheet.  
**Guide:** Module 3, Cost Stack.

### C2. Choose Target Margin

**Do:** Enter a Target Margin you chose (not a universal “right” number).

### C3. Choose Margin Guardrail

**Do:** Enter a Margin Guardrail distinct from Target Margin. Confirm you understand floor vs target.

### C4. Use the Pricing & Margin Calculator

**Do:** Generate prices from the calculator. Confirm you are using **margin**, not markup.

**Tool:** `content/bbos/bbos-pricing-margin-calculator-v1.xlsx` (copy).  
**Guide:** Module 3 + calculator Start Here / Notes.

### C5. Price Entry / Core / Premium

**Do:** Record ladder prices from calculator outputs (fictional). Update Offer Ladder placeholders in your workbook copy if helpful.

### C6. Price Optional items

**Do:** Price at least two Optional items through the calculator.

### C7. Test Discount Guardrails

**Do:** Invent a customer asking below your Guardrail. Follow the Module 3 decline / hold path. Note whether the tools made the decision clear.

### C8. Test Exception Approval

**Do:** Invent one bounded Exception with an end date. Confirm you would know where to write it and when it expires.

**Pause check:** Did you feel tempted to invent a new formula? If yes, log it.

## Part D — Module 4: Weekly Operating Rhythm

### D1. Design a Weekly Operating Rhythm

**Do:** Choose Planning, Pipeline/Follow-Up, and Close windows that fit your fictional delivery load. No universal Monday required.

**Tool:** `My Rhythm`.  
**Guide:** Module 4, Design Your Weekly Operating Rhythm.

### D2. Schedule Planning Block

**Do:** Run one Planning Block (25–40 min target ~30). Produce top 3 outcomes, confirm Sell + Close windows, name one delivery risk.

**Tool:** `Week Plan`.

### D3. Define Daily Anchors

**Do:** Write **2–3** anchors only. Tick a few fictional days.

**Tool:** `Daily Anchors`.

### D4. Schedule Pipeline and Follow-Up Block

**Do:** Run one Sell block (30–60 min target ~45) using your pipeline and cadence — not rebuilding Module 2.

### D5. Complete Pricing Checkpoint

**Do:** Answer notice-only questions. Do **not** analyze runway or full Core Numbers. If you need a price recalc, open the calculator, then return.

**Tool:** `Pricing Checkpoint`.

### D6. Complete Delivery Quality check

**Do:** Write 3–5 quality bullets; run Before / During / After once for a fictional job.

**Tool:** `Delivery Quality`.

### D7. Run the Weekly Close

**Do:** Complete Close inside the 45-minute normal-week ceiling.

**Tool:** `Weekly Close`.

### D8. Complete Next-Week Handoff

**Do:** Fill exactly four lines: top priority; first unresolved follow-up; first delivery/capacity risk; next Planning window. Stop — do not full-plan next week.

### D9. Test Catch-Up Protocol after a fictional disruption

**Do:** Invent one disruption mid-Sell-block (urgent job, sick day, vehicle issue). Pause, write Catch-Up, recover before/at Close. Do not treat it as personal failure.

**Tool:** `Catch-Up Protocol` + Close/Handoff.

**Pause check:** Did the system still feel usable after disruption?

---

## Part E — Simulated weekly cycle (required)

Simulate **one complete week** end to end:

```text
Plan → Deliver → Sell and Follow Up → Review → Close
```

Minimum evidence:

- [ ] Planning Block completed  
- [ ] Delivery + anchors + quality check touched  
- [ ] Pipeline/Follow-Up Block completed  
- [ ] Pricing Checkpoint completed (notice only)  
- [ ] Weekly Close + Next-Week Handoff completed  
- [ ] One disruption + Catch-Up tested  

Optional: mark the week on `13-Week Tracker` in your workbook copy.

## After the walkthrough (same day or next morning)

1. Transfer every pause into `docs/BBOS_PHASE_TWO_USABILITY_BACKLOG.md` (or a working copy of that template).  
2. Do **not** start fixing.  
3. Follow the prioritization method in the backlog file.  
4. Record a **go / no-go** recommendation for starting Module 5 architecture.

## Exit criteria

The Founder Walkthrough is **complete** only when all of the following are true:

- [ ] Modules 1–4 have been tested end to end  
- [ ] Pricing & Margin Calculator has been used  
- [ ] Weekly Operating Rhythm Workbook has been used  
- [ ] At least one complete weekly cycle has been simulated  
- [ ] One disruption has been tested with Catch-Up  
- [ ] Every pause has been logged  
- [ ] No fixes were made during testing  
- [ ] The backlog has been reviewed and grouped  
- [ ] V1 blockers have been identified (even if the list is empty)  
- [ ] A go/no-go recommendation for Module 5 architecture has been recorded
